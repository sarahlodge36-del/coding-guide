You Know More Than You Think

The HTML you've learned in Chapters 1 to 9 covers everything you need to build real, working webpages. But HTML goes further than the basics — and knowing what exists beyond them makes you a better developer even before you learn it in depth.

This page is an overview of the intermediate and advanced HTML concepts you'll encounter as you progress. Some of these are covered in the paid section of this guide. Others you may pick up through practice and reading. Either way — this is what's out there.

Semantic HTML — Going Deeper

You've already met the main semantic elements — header, nav, main, section, article, aside, footer. But there are more, and using them properly makes a real difference to accessibility and SEO.

  • <main> — there should only ever be one main element per page. It contains the primary content of the page.
  • <time datetime="2024-01-15"> — marks up dates and times in a machine-readable way
  • <mark> — highlights text as if with a highlighter pen
  • <details> and <summary> — creates a collapsible section without any JavaScript
  • <dialog> — a built-in modal dialog element
  • <progress> — a built-in progress bar
  • <meter> — represents a scalar measurement within a known range
<details>
  <summary>Click to expand</summary>
  <p>Hidden content that appears on click — no JavaScript needed!</p>
</details>

ARIA and Accessibility

ARIA stands for Accessible Rich Internet Applications. It's a set of attributes you can add to HTML elements to make them more accessible to screen readers and assistive technologies — especially for interactive content that HTML alone can't fully describe.

  • role="button" — tells screen readers an element behaves like a button
  • aria-label="Close menu" — provides a text label for elements with no visible text
  • aria-hidden="true" — hides decorative elements from screen readers
  • aria-expanded="false" — tells screen readers whether a collapsible section is open or closed
  • aria-live="polite" — tells screen readers to announce dynamic content changes
<button aria-label="Close navigation menu" aria-expanded="false">
  <span aria-hidden="true">✕</span>
</button>

The first rule of ARIA is: don't use ARIA if you can use native HTML instead. A real button element is always better than a div with role="button". Use ARIA to fill the gaps, not to replace good HTML.

Meta Tags — Beyond the Basics

You've already used the description meta tag. There are several more worth knowing about.

  • <meta name="robots" content="index, follow"> — tells search engines whether to index the page
  • <meta name="author" content="Sarah"> — names the page author
  • <meta name="theme-color" content="#0a0a0a"> — sets the browser chrome colour on mobile
  • <link rel="canonical" href="https://yoursite.com/page"> — tells search engines which is the definitive version of a page

Open Graph Tags

Open Graph tags control how your page appears when shared on social media — the image, title, and description that appear in a Twitter or Facebook preview card.

<meta property="og:title" content="My Coding Guide" />
<meta property="og:description" content="Learn HTML, CSS and JavaScript from scratch." />
<meta property="og:image" content="https://yoursite.com/preview.jpg" />
<meta property="og:url" content="https://yoursite.com" />

These are worth adding to any page you want to share. The difference between a page with and without Open Graph tags when shared on social media is significant.

Advanced Form Attributes

Form inputs have a lot more attributes than the basics covered in Chapter 7.

  • required — prevents the form from submitting if the field is empty
  • placeholder="Enter your email" — shows hint text inside the input
  • autocomplete="email" — hints to the browser what kind of data to autofill
  • pattern="[0-9]{5}" — validates input against a regular expression
  • min="0" max="100" — sets minimum and maximum values on number inputs
  • type="email" — validates email format automatically on mobile
  • type="tel" — shows a numeric keyboard on mobile
  • type="date" — shows a date picker
  • type="range" — shows a slider
  • type="color" — shows a colour picker
<input
  type="email"
  placeholder="your@email.com"
  required
  autocomplete="email"
/>

Data Attributes

Data attributes let you store custom data on HTML elements — information that isn't visible on the page but that JavaScript can read. You've already used these in the adventure game!

<button data-index="0" data-mode="question">Answer A</button>

Any attribute starting with data- is a valid data attribute. You can name them anything you like after the hyphen. JavaScript reads them using getAttribute('data-index') or the dataset property.

var btn = document.querySelector('button');
btn.dataset.index; // '0'
btn.dataset.mode; // 'question'

Responsive Images — picture and srcset

Rather than serving the same large image to every device, you can provide different image sizes for different screen sizes using srcset or the picture element.

<img
  src="photo-800.jpg"
  srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1200.jpg 1200w"
  sizes="(max-width: 600px) 400px, 800px"
  alt="A photo"
/>

The browser picks the most appropriate image based on the screen width. This saves bandwidth on mobile and improves page load speed significantly.

iframes

An iframe embeds another webpage inside your page. You've likely already used one without realising — YouTube embed codes use iframes.

<iframe
  src="https://www.youtube.com/embed/VIDEO_ID"
  width="560"
  height="315"
  allowfullscreen
></iframe>

Be careful embedding third-party content — it can affect page performance and introduces security considerations.

HTML Entities — Going Further

You already know &copy; and &nbsp;. Here are some others worth having to hand.

  • &mdash; — em dash —
  • &ndash; — en dash –
  • &laquo; — left double angle quotation mark «
  • &raquo; — right double angle quotation mark »
  • &trade; — trademark symbol ™
  • &reg; — registered trademark ®
  • &euro; — euro sign €
  • &pound; — pound sign £
  • &hearts; — heart ♥
