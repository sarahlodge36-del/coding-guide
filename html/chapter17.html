Remember semantic elements from Chapter 8? Let's actually use them properly now. 😎

Why We're Coming Back to This

Back in Chapter 8 you met semantic HTML5 elements — header, nav, main, section, article, and footer. They're covered properly here because now that you've seen how CSS controls layout, it's much easier to understand how these elements fit into a real page structure.

Traditional vs Semantic Structure

Before HTML5, developers used div elements with id and class names to indicate the role of each section — div id="header", div id="nav", and so on. This worked, but it gave no real indication of what each section actually was just from looking at the tag itself.

The new HTML5 elements describe the kind of content they contain. They behave like divs by default — they don't do anything magical on their own — but they give your markup a clear, logical structure that's more meaningful to other developers, browsers, and screen readers.

Headers and Footers — header, footer

header and footer can be used for the main header and footer of the page, but they can also be used inside individual article or section elements to give each one its own header or footer.

<header>
  <h1>Sarah's Coding Guide</h1>
  <nav>...</nav>
</header>

<footer>
  <p>&copy; My Site 2024</p>
</footer>

Navigation — nav

The nav element is used for the main blocks of navigation links on a page — things like the primary site menu. Not every group of links needs to be in a nav, just the major navigation blocks.

<nav>
  <ul>
    <li><a href="index.html">Home</a></li>
    <li><a href="about.html">About</a></li>
  </ul>
</nav>

Sections — section

The section element groups related content together. Typically each section would have its own heading. It's not a generic wrapper like div — it's meant for thematically related groups of content.

<section>
  <h2>Most Popular</h2>
  <p>...</p>
</section>

Articles — article

The article element acts as a container for any section of a page that could stand alone — a blog post, a news story, a comment, a forum post. If you could imagine the content being republished independently, it belongs in an article.

<article>
  <h2>My First Blog Post</h2>
  <p>Today I learnt about HTML5...</p>
</article>

Aside — aside

The aside element has two uses. Inside an article it contains information related to that article but not essential to it — like a pull quote. Outside an article it acts as a container for content related to the whole page — like a sidebar of related links.

<aside>
  <h2>Related Topics</h2>
  <ul>...</ul>
</aside>

Figures and Captions — figure, figcaption

The figure element is used to contain any content that is referenced from the main flow of text — most commonly images, but also diagrams, code examples, or charts. The figcaption element sits inside figure and provides a caption for it.

<figure>
  <img src="images/cat.jpg" alt="A ginger cat" />
  <figcaption>Our cat Marmalade, age 3.</figcaption>
</figure>

You can include more than one image inside a single figure element as long as they all share the same caption. Using figure and figcaption together is better for accessibility than a plain img tag followed by a paragraph — screen readers understand the relationship between the two.

div Isn't Going Anywhere

The div element is still the right choice when you need a container purely for styling purposes and none of the semantic elements fit. Think of the new HTML5 elements as meaningful alternatives to div — use them when the content fits, use div when it doesn't.

🔨 Now Let's Build!

Open your index.html file in Notepad. We're going to upgrade those plain div elements from Chapter 8 into proper semantic HTML5 elements. Find your existing structure and update it:

<!-- change this -->
<div id="header">...</div>

<!-- to this -->
<header>...</header>

<!-- and change this -->
<div id="content">...</div>

<!-- to this -->
<main>...</main>

<!-- and finally this -->
<div id="footer">...</div>

<!-- to this -->
<footer>...</footer>

Also wrap your photo from Chapter 5 in a figure element and add a figcaption underneath it:

<figure>
  <img src="images/myphoto.jpg" alt="A photo I chose" width="400" height="300" />
  <figcaption>A photo I like.</figcaption>
</figure>

Now update your styles.css file — change #header to header, #content to main, and #footer to footer. Also add a style for figcaption:

figcaption {
  text-align: center;
  font-size: 0.85em;
  color: #888888;
  margin-top: 5px;
}

Save both files and refresh. Your photo now has a proper caption underneath it, and your page structure is fully semantic from top to bottom!
