What is a Script?

A script is a series of instructions that a computer can follow to achieve a goal. Think of it like a recipe — each step needs to happen in the right order, and the computer follows each instruction precisely, one at a time.

Scripts can be short — just a few lines. Or they can be thousands of lines long. Either way, the computer reads them from top to bottom, doing exactly what each line says.

Unlike a recipe though, a script can make decisions. It can say "if this happens, do that — but if something else happens, do this instead." That ability to make decisions is what makes programming powerful.

How Do You Write a Script?

Writing a script starts with stating your goal. Before you write a single line of code, ask yourself — what do I actually want this to do?

Then break that goal down into smaller tasks. And break those tasks down further into individual steps. Each step eventually becomes a line of code.

This process — breaking a big goal into smaller and smaller pieces until each piece is simple enough to write as a single instruction — is the core skill of programming. The code itself is almost secondary. The thinking comes first.

How Computers Think

Computers are fast but they are also very literal. They do exactly what you tell them — nothing more, nothing less. If your instructions are unclear or have a mistake in them, the computer won't guess what you meant. It will either do the wrong thing or stop working entirely.

This is why programming feels hard at first. Not because the concepts are complicated, but because you have to be more precise than you're used to being. In everyday life, "make me a cup of tea" is a perfectly clear instruction. To a computer you'd need to specify: boil the kettle, get a mug, add a teabag, pour the water, wait, remove the teabag, add milk, stir. Every single step, in order, with nothing assumed.

The good news is that once you get used to thinking that way, it becomes second nature.

How HTML, CSS and JavaScript Work Together

You've already learned two of the three languages that power every webpage. Here's how they fit together:

  • HTML — gives the page its structure and content. The bones.
  • CSS — controls how everything looks. The skin.
  • JavaScript — makes the page respond and behave. The nervous system.

All three live together. JavaScript sits alongside your HTML and CSS — either in a separate .js file linked to your HTML page, or written directly inside a script tag in your HTML.

<script src="script.js"></script>

That line goes just before the closing body tag — at the very bottom of your HTML, so the page loads first before the JavaScript runs.

Objects, Properties and Methods

JavaScript uses a concept called objects to represent things. An object is anything you can describe or interact with — a button, an image, a piece of text, even the whole browser window.

Every object has properties — characteristics that describe it. A hotel room object might have properties like room number, floor, and whether it has a sea view.

Every object also has methods — things it can do or things that can be done to it. A hotel room object might have methods like book(), cancel(), and checkIn().

You'll see this pattern everywhere in JavaScript. Don't worry about memorising it right now — just start recognising it when you see it.

Events

JavaScript responds to events. An event is something that happens — a user clicks a button, moves their mouse, presses a key, or a page finishes loading.

When an event happens, JavaScript can be written to respond to it. This is what makes pages interactive. The user does something — JavaScript notices — and something on the page changes.

Almost everything in JavaScript starts with an event of some kind. By the end of this section you'll be using events constantly.

A New Tool — CodePen

From this chapter onwards we're using CodePen instead of Notepad. Go to codepen.io and create a free account before you start — it only takes a minute and means your work saves automatically every time you hit Ctrl+S. Without an account your work only lives in the browser tab — close it and it's gone.

Once you're signed in, create a new pen and you'll see three files down the left-hand side — index.html, style.css, and script.js — with a live preview on the right. Whatever you type appears instantly. No saving, no refreshing. Just immediate feedback.

⚡ CodePen Quick Guide

  • index.html — CodePen has already filled this in with a starter skeleton: the DOCTYPE, html, head, and an empty body. You don't rewrite those. Your HTML goes inside the existing body tags — that's the part between <body> and </body>.
  • style.css — CodePen puts a little demo styling in here. Select it all, delete it, and write your own CSS rules. Nothing extra to set up — it's already linked to your HTML for you.
  • script.js — this empty file is where all your JavaScript goes. It's already connected to your HTML too, so anything you write here runs on the page.
  • The preview panel — updates live as you type. If something goes wrong, check the browser console — click the Console button at the bottom of the screen.

One thing to check: scroll to the bottom of index.html and look for a line that says <script src="./script.js"></script> just before </body>. CodePen usually adds this for you — it's the line that connects your JavaScript to the page. If it's missing, add it yourself, or your buttons won't do anything.

⚡ The Code Machine Quest

Over the next 6 chapters you're going to build a fully playable text adventure game called The Code Machine Quest. The legendary Code Machine — capable of generating any website in existence — has been dismantled. Five components are hidden across five dangerous digital realms. You have to get them back.

Each chapter adds a new feature to the game as you learn a new JavaScript concept. By Chapter 25 you'll have a fully working, fully playable game you built entirely from scratch.

Let's start with the title screen. 🚀

Click index.html in CodePen. You'll see it already has a skeleton filled in for you. Find the <body> tags and type this inside them — between <body> and </body>:

<div id="game">
  <h1 id="title">THE CODE MACHINE QUEST</h1>

Now click script.js — this empty file is where your very first JavaScript goes. Type this in:

document.getElementById('startBtn').addEventListener('click', function() {
  var name = document.getElementById('nameInput').value;
  if (name === '') {
    document.getElementById('message').textContent = 'You need to enter your name, coder!';
  } else {
    document.getElementById('message').textContent = 'Welcome, ' + name + '. XGENFUTBOT is watching. The quest begins...';
  }
});

Type your name in the box and click the button. You should see a personalised message appear below it. That's JavaScript reading what you typed, checking it isn't empty, and writing a response back to the page.

That is your first working JavaScript. It's also the first screen of your adventure game. 🚀

🛠️ Nothing showing up? Check this first

If your page looks plain and unstyled, or the button does nothing when you click it, the usual cause is a missing link between the files. Scroll to the bottom of index.html and make sure this line is there, just before </body>:

<script src="./script.js"></script>

That's the line that connects your JavaScript to the page. CodePen usually adds it for you, but if it's missing, add it yourself and everything springs to life.
