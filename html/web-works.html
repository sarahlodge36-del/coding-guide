How Does the Web Actually Work?

Before we start writing code it helps to understand what's actually happening when someone visits a website. You don't need to know all the technical details — but having a basic picture in your head will make everything else make more sense.

When you type a web address into your browser and hit Enter, a lot of things happen very quickly behind the scenes. Let's walk through it.

Browsers

A browser is the program you use to access the web. Chrome, Edge, Firefox, Safari — they're all browsers. When you visit a website, the browser sends a request to a web server asking for the page. The server sends back the HTML, CSS, and JavaScript files that make up that page, and the browser reads those files and turns them into the webpage you see on screen.

This is why what you're learning matters — you're learning to write the files that browsers read. The browser is your audience. Everything you code is ultimately written for the browser to interpret and display.

Different browsers can display things slightly differently, which is why developers always test their sites in more than one browser.

Web Servers

A web server is a computer that is permanently connected to the internet and stores website files. When you type a web address, your request travels across the internet to that server, the server finds the right files, and sends them back to your browser.

Web servers run specialised software that handles thousands of requests at once — from people all over the world, all asking to see the same website at the same time.

When you're building your site locally on your computer, your own machine is acting as a kind of web server — just one that only you can access. When you're ready to share your site with the world, you upload your files to a real web server and anyone can access them.

DNS — Domain Name System

Every computer connected to the internet has a unique numerical address called an IP address — something like 142.250.187.46. When you type google.com into your browser, how does your computer know which server to connect to?

That's where DNS comes in. DNS stands for Domain Name System and it works a bit like a giant phone book for the internet. When you type a web address, your computer contacts a DNS server which looks up that domain name and returns the IP address of the web server where that site lives. Your browser then connects to that IP address and requests the page.

The whole process happens in milliseconds — so fast you never notice it. But every single time you visit a website, DNS is working in the background to make it happen.

Devices

People access the web from all kinds of devices — desktop computers, laptops, tablets, mobile phones, smart TVs, game consoles, and more. Each device has a different screen size, different processing power, and sometimes a different browser.

This is something you need to think about as a web developer. A page that looks great on a large desktop monitor might be unusable on a small phone screen. A design that works perfectly in Chrome might look broken in an older browser.

This is why responsive design exists — building pages that adapt to whatever device they're being viewed on. We'll cover this properly in the CSS section, but it's good to have it in the back of your mind from the start.

Screen Readers

A screen reader is software that reads the content of a webpage out loud for people who are blind or visually impaired. Screen readers don't see the page visually — they read through the HTML and announce what each element is and what it contains.

This is why writing good HTML matters beyond just making things look right in a browser. The way you structure your HTML — using proper headings, descriptive alt text on images, labels on form fields — directly affects whether someone using a screen reader can understand and navigate your page.

Accessibility isn't an optional extra. It's part of writing good code. Throughout this guide we'll make sure everything we build works for everyone — not just sighted users on desktop computers.

Putting It All Together

So when someone visits your website here's what actually happens:

  • They type your web address into their browser
  • Their computer contacts a DNS server to find your web server's IP address
  • Their browser sends a request to your web server
  • Your web server sends back your HTML, CSS, and JavaScript files
  • Their browser reads those files and displays your webpage
  • The whole thing happens in a fraction of a second

Every website on the internet works this way — from a simple personal page to Google, Amazon, or the BBC. The scale is different but the process is the same.

Now you know what's happening under the hood — let's start building. 🚀
